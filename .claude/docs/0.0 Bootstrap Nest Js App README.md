Это шаблон бэкенда на NestJS 11 с уже подключёнными базой, конфигом и валидацией. Бизнес-логики пока нет: users и auth пустые.

Стек

- HTTP-сервер: Fastify вместо Express по умолчанию (@nestjs/platform-fastify). Поэтому в main.ts используется app.register(...), а не app.use(...).
- БД: PostgreSQL, ORM TypeORM. Для транзакций есть typeorm-transactional (декоратор @Transactional()).
- Конфиг: @nestjs/config и Joi для валидации .env.
- Валидация запросов: class-validator и class-transformer через ValidationPipe.
- Прочее: @nestjs/throttler (rate limit), @nestjs/terminus (health check), cookies и сжатие ответов.
- Инструменты: Jest, ESLint, Prettier, Docker Compose для Postgres.

Структура src/

main.ts — точка входа. В нём по порядку:
- инициализируется транзакционный контекст;
- создаётся Fastify-приложение;
- подключаются сжатие и глобальный ValidationPipe({ whitelist: true }), который отбрасывает поля, не описанные в DTO;
- включается CORS для localhost:5174, 4200 и 8080 с credentials, то есть с куками;
- регистрируется fastifyCookie с секретом из конфига;
- приложение слушает порт из PORT.

core/ — инфраструктура, не связанная с бизнес-логикой:
- app/app.module.ts — корневой модуль, собирает всё остальное.
- config/ — свой ConfigService поверх Nest-го. Он типизирует ключи через Config и валидирует .env через Joi при старте. Если обязательной переменной нет, приложение не запустится. Новая переменная добавляется в config.types.ts и config.validation.ts.
- database/ — подключение TypeORM к Postgres. Сущности *.entity.ts подхватываются автоматически, миграции лежат в src/database/migrations.
- health/ — GET /health. Если HEALTH_CHECK_ENABLED=false, он просто отвечает {status:'ok'}.
- throttler/ — настройки лимита запросов (TTL и количество из .env).

database/ — data-source.ts нужен только для CLI TypeORM (npm run migration:generate, migration:run и т.д.). Приложение его не использует.

modules/ — здесь будет ваша логика. Сейчас там пустые AuthModule и UsersModule.

Остальное

- .env.example — копируете в .env. Там порт 3007, секрет для кук и параметры Postgres.
- docker-compose.yml — docker compose up -d поднимает Postgres 18.
- test/ и *.spec.ts — тесты. Unit-тесты есть для конфига и health.
- Алиас @/* указывает на src/*.

Что стоит знать заранее

1. AuthModule не импортирован в AppModule. Подключите его, когда начнёте писат
2. Throttler сейчас не защищает эндпоинты. Он сконфигурирован, но не зарегистружен провайдер { provide: APP_GUARD, useClass: ThrottlerGuard }. Для логина ирегистрации лимит особенно важен.
3. test/app.e2e-spec.ts — остаток от стартового шаблона Nest. Он ждёт GET / с Hello World!, а такого контроллера нет, так что e2e упадёт. Тест также написан под Express, а не Fastify.
4. В README написано, что валидация идёт через Joi. На деле Joi проверяет тольроверяет class-validator через DTO.
5. Пример алиаса в README (@config/...) неверный. Настроен только @/*.
6. Для работы с файлами (ваша третья задача) понадобится плагин вроде @fastify/multipart. Он не установлен, а с Fastify нельзя использовать multer, который обычно показывают в курсах по Express.
7. В main.ts у вас незакоммиченные изменения, это только форматирование Prettier. .vscode/ тоже пока не в git.

Если хотите, могу разобрать, как по этой структуре строить users и auth: сущность, DTO, хеширование паролей, JWT в httpOnly-куках. Для Fastify это делается чуть иначе, чем в большинстве курсов.
